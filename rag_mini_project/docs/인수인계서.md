## 1. 프로젝트 한 줄 요약

금융 문서(PDF 23개)를 검색해 근거와 함께 한국어로 답하는 **RAG Agent 실습**이다. 청킹·검색·기본 RAG vs Agent를 같은 질문 세트로 비교하고 최종 설정을 고르는 것이 목표이며, **계획한 실험과 평가는 모두 끝났다.** 요구사항 원문은 `README.md`(프로젝트 루트).

## 2. 사용자와 일하는 방식 (꼭 지킬 것)

- **한국어로, 짧게** 답한다. 길게 쓰면 지적받았다.
- **커밋·푸시는 사용자가 말할 때만** 한다. 지금 미커밋 상태이고, 사용자가 "나중에 한다"고 했다.
- **`docs/회고.md`는 건드리지 않는다.** 사용자가 나중에 직접 다시 고치기로 했다.
- 오래 걸리는 작업은 시작할 때 예상 시간을 말하고, 예상보다 오래 걸리면 바로 알린다(36분 방치로 지적받음).
- 확인하지 못한 것은 확인하지 못했다고 쓴다. 단일 실행 결과로 결론 내지 않는다.
- 사용자는 토큰이 적고 인터넷이 불안정하다. 불필요한 실행·긴 설명을 피한다.

## 3. 현재 상태

- **끝남:** 문서 추출, 청킹·색인, 검색 평가(B0, E1~E6), 기본 RAG·판정·답변 평가(반복 포함), Agent 구현·평가, 합친 설정(E8), 문서 정리. 실행 기록 76개(검색 35, 답변 33, Agent 8).
- **최종 선택:** 두 세트 모두 **E3-b**(구조 단위 parent-child, k=5, similarity). 비용을 줄이려면 기본 세트에서 E8a(k=3).

| 세트 | B0 (pass / 핵심 항목 포함) | E3-b | 토큰 |
|---|---|---|---|
| 기본(용어집+약관, 100문항) | 70.3% / 89.7% | 80.5% / 94.6% | 1.3배 |

## 7. 자주 쓰는 명령

```bash
python -m rag.report                       # 설정별 평균과 [최소–최대]
python -m rag.report --runs                # 설정별 실험 ID
python -m rag.compare --baseline-of <ID>   # 기준 대비 차이와 나아진/나빠진 문항 수
python -m rag.failure_analysis <ID>        # 실패 원인 분류
python -m rag.answer_eval --workers 16 --name <이름> --collection <컬렉션> --baseline <기준 ID> [--mode agent] [--k 3]
```
새 실험은 반드시 `--baseline`으로 돌려서 `config.json`의 `changes`에 **바꾼 요소 하나만** 잡히는지 확인한다.

## 8. 평가 해석 규칙

- 같은 설정을 다시 돌려도 pass가 5~6%p, 핵심 항목 포함이 1~3%p 달라진다(temperature 0인데도). **5%p 안쪽 pass 차이는 무시**하고, 비교는 핵심 항목 포함을 먼저 본다. 최종 후보는 2회 이상 돌려 평균과 범위로 말한다.
- `pass` = 핵심 항목 모두 포함 AND 금지 내용 없음 AND 답변·보류 계열이 기대와 같음. 엄격해서 단서 한 문장만 빠져도 불합격이다.
- 모델 API가 요청을 차단하면(`block_reason`) 제외하지 않고 실패로 센다(`blocked`).
- Agent의 근거 준수가 낮게 나오는 것은 품질 하락이 아니라, 검색 없이 거절할 때 쓴 위험 안내를 '근거 없는 주장'으로 세기 때문이다.
- 응답 시간은 동시 처리 수(대부분 6, 마지막 10개 실행은 16)가 다르면 비교할 수 없다.

## 9. 함정 (겪은 문제와 피하는 법)

| 문제 | 피하는 법 |
|---|---|
| Python이 한글을 cp949로 읽어 실패(`git` 호출, `print`) | `subprocess`에 `encoding="utf-8"`, 스크립트 첫 줄 `sys.stdout.reconfigure(encoding="utf-8")` |
| Bash의 긴 `python - <<EOF` 스크립트가 따옴표 오류로 실패 | 스크립트를 파일로 저장해서 실행 |
| 도구의 중단 요청이 스크립트와 자식 프로세스를 실제로 멈추지 못함 | 중단 뒤 PowerShell `Get-CimInstance Win32_Process`로 직접 확인. PID 종료는 사용자 승인이 필요했다 |
| 임베딩 호출이 응답 없이 36분 멈춤 | 이미 시간 제한(120초)·재시도·문항별 15분 제한을 넣었다. 일괄 실행 때는 새로 끝나는 간격을 감시한다 |
| 동시 호출에서 `client has been closed` | 클라이언트 생성에 잠금을 넣었다(`rag/llm.py`) |
| 생성 답변이 중간에 잘림 | 생각(thinking) 토큰이 출력 한도를 먼저 쓴다. 생성은 생각을 끈다 |
| 같은 설정인데 MMR 결과가 실행마다 다름 | Chroma `ef_search`를 1000으로 고정했다 |
| 쪽 표시 `(printed 82)`를 못 읽음 | `md_parser.PAGE_RE`가 처리한다 |
| 동시 처리 수를 크게 올리면 | 합쳐서 스레드 48개 이하, Postgres 연결 수(기본 100)에 주의. 429는 재시도로 흡수되어 실패보다 느려진다 |
| 시험 실행이 정식 기록을 어지럽힘 | `RAG_RESULTS_DIR=<폴더>`로 따로 저장 |
| 한글 파일명이 코드 버전 조회를 깨뜨렸음 | 고쳤지만, 새 파일을 만들 때 `git status` 출력이 파이썬에서 읽히는지 의식한다 |
