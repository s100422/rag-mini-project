# 실험 결과: Agent 개선 (E3-b 위의 Agent v2)

작성 2026-10-22. 원본 결과는 `docs/experiment_results.md`(3.4절 Agent), 임베딩은 gemini-embedding-001 그대로다. 이 문서의 실험은 모두 **E3-b(구조 단위 parent-child, k=5, similarity) 위**에서 돌렸고, 판정 모델·프롬프트·질문 세트는 원본과 같다. 기본 세트 100문항, 확장 세트 80문항, 설정마다 3회 반복(평균 [최소–최대]). 실행 26개 모두 오류·차단 0.

## 1. 무엇을 바꿨나

원본 결과(3.4절)에서 Agent의 효과는 질문 분석·분기에서만 나왔고(E7a), 재검색은 비용만 늘렸다(E7b). parent-child(E3-b)는 답할 수 있는 질문에 강하고 되묻기에 약해서 둘이 반대였다. 확장 세트의 실패는 근거를 다 찾고도 단서·한계 문장이나 행동 안내를 빠뜨리는 것이 가장 컸다(원본 4절). 그래서:

| 설정 | 구성 | 바뀐 점 |
|---|---|---|
| E3-b | 기본 RAG(검색 1번 → 답변 1번) | 기준 |
| C0 | E3-b + 프롬프트 v2, **Agent 없음** | 시스템 프롬프트에 규칙 9~11 추가: 근거 있는 부분은 답하고 없는 부분만 보류 / 예시·표 수치의 한계 한 문장 / 피해·분쟁이면 다음 행동 안내. 대조군 |
| A1 | E3-b + 현재 Agent, 재검색 끔(`retry=0`) | 질문 분석 → 검색 → 답변. 원본 E7a를 E3-b 위에 얹음 |
| A2 | A1 + **Agent v2** | 분석 노드가 `needs_caveat`(수치·자격 질문)·`needs_next_steps`(피해 상황)를 함께 판단하고, 답변 지침에 C0의 규칙을 필요한 것만 붙임. LLM 호출은 A1과 같다 |
| A3 | A2 + 분석 노드만 `gemini-3.1-flash-lite` | 비용 절감 시험. 답변 모델(`gemini-3.8-flash`)과 판정 모델(`gemini-2.5-pro`)은 그대로 |
| A4 | A2 + 답변 노드도 시스템 프롬프트 v2 | Agent v2와 프롬프트 v2를 합침(5절). 같은 규칙이 시스템 프롬프트와 지침에 두 번 들어간다 |

C0이 이 실험의 핵심 대조군이다. 이것이 없으면 프롬프트 개선의 효과를 Agent의 효과로 잘못 말하게 된다. `gemini-2.5-pro`는 판정 모델이고 Agent 노드는 원래 모두 flash였다. 판정을 바꾸면 이전 결과와 비교할 수 없어서 pro로 고정했다.

## 3. 해석

1. **기본 세트에서는 Agent도, 프롬프트도 E3-b보다 나아지지 않았다.** E3-b, C0, A1, A2가 pass 79.7~81.3%, 포함 94.2~94.6%로 모두 오차 안이다. 개선을 기대할 여지가 거의 남지 않은 구간(포함 94%)이다.
2. **Agent는 행동 판단을 개선하지만 다른 곳에서 잃어 합이 같다.** 되묻기 25 → 46%(A1)·42%(A2), 보류 81 → 92·86%, 거절 83 → 90·93%로 원본 E7a와 같은 방향이다. 반면 정정이 81 → 67%로 나빠졌다(7문항). 되묻기가 8문항뿐이라 확정은 못 하지만, parent-child의 약점(되묻기)을 질문 분석이 메운다는 가설은 방향이 맞았다.
3. **확장 세트에서 v1 Agent(A1)는 E3-b보다 나쁘다**(pass 72.1 → 67.9, 포함 89.0 → 86.8). **Agent v2의 지침이 이를 되돌렸다**(A1 67.9 → A2 75.0, 범위가 겹치지 않음). 분석 노드가 수치·자격 질문(80문항 중 60개)과 피해 상황(5개)을 가려내 지침을 붙인 것이 효과가 있었다.
4. **그러나 같은 지침을 Agent 없이 쓴 C0이 A2와 같거나 낫다**(확장 pass 76.2 vs 75.0, 포함 90.2 vs 88.4, 차이는 오차 안). 즉 **개선의 원인은 Agent 구조가 아니라 답변 지침(프롬프트)**이다. C0은 호출 1번, 응답 4.7초로 A2(2번, 7.9초)보다 싸다. 지침을 항상 켜도 기본 세트에서 손해가 없었다(80.3 vs 79.7).
5. **가벼운 모델로 분석 노드를 바꾸는 것(A3)은 권하지 않는다.** 두 세트에서 A2보다 낮고(기본 pass −4.3, 확장 포함 −3.6), 근거 준수와 정정 문항이 나빠졌다(확장 근거 준수 97.4 → 93.1%, 기본 정정 67 → 43%). 절약은 응답 1.3~1.6초뿐이다. 확장 세트에서 `needs_caveat`를 80문항 중 76개에 켜서 지침이 거의 항상 붙었다는 점이 한 원인으로 보이나(A2는 60개) 확인하지 않았다.
6. **비용:** Agent(A1·A2)는 LLM 호출이 2배, 응답이 1.4~1.7배(4.5 → 6.5~7.9초)지만 입력 토큰은 E3-b의 +5~14%뿐이다(A1 +5~6%, A2 기본 +14%, 확장 +7%. 재검색이 없어서). 원본 E7(토큰 1.9배, 3회 호출)보다 훨씬 싸졌다.
7. **근거 준수가 낮아 보이는 것(기본 세트 Agent 87~88%)은 원본과 같은 지표의 성격이다**(검색 없이 거절할 때 쓴 위험 안내를 '근거 없는 주장'으로 센다). 확장 세트에서는 Agent가 근거 준수(97.2~97.4 vs 99.4~99.8)와 **답변·보류 일치**(A2 95.8%, C0 100%)에서 약간 낮다. 확장 질문은 모두 '답변'이 기대인데 Agent의 질문 분석이 4% 정도를 되묻기·보류로 잘못 분기하는 것으로 보이나(문항별 확인은 하지 않았다) 이 차이가 pass에는 거의 드러나지 않았다.

## 4. 합친 설정 A4 (Agent v2 + 시스템 프롬프트 v2)

A2(Agent v2)와 C0(프롬프트 v2)을 합친 설정이다(`--agent-options retry=0,v2=1,sys2=1`). 두 세트 3회씩, 오류·차단 0.

| 기본 | E3-b | 79.7 [78–83] | 94.5 | 99.5 | 91.7 | 2,334 | 1.00 | 4.5 |
| 기본 | C0 | 80.3 [78–82] | 94.6 | 99.3 | 93.0 | 2,484 | 1.00 | 4.4 |

기본 세트 기대 행동별 pass %(반복 평균): 답변(63) E3-b 86 / A2 85 / **A4 86**, 정정(7) 81 / 67 / 67, 되묻기(8) 25 / 42 / **46**, 보류(12) 81 / 86 / **92**, 거절(10) 83 / 93 / 93.

- **기본 세트: A4가 가장 높지만 오차 범위다.** pass 83.0%는 E3-b보다 +3.3, A2보다 +1.7, C0보다 +2.7%p로 모두 5%p 안쪽이고 범위도 겹친다(A4 81–85, E3-b 78–83). 핵심 항목 포함은 94.9%로 같다.
- **행동 문항에서는 가장 균형이 좋다.** Agent의 이득(되묻기 25 → 46%, 보류 81 → 92%, 거절 83 → 93%)을 지키면서 A1·A2에서 줄었던 '답변' 문항(83, 85%)이 E3-b 수준(86%)으로 돌아왔다. 정정은 여전히 낮다(67%, 7문항).
- **확장 세트: 합쳐도 이득이 없다.** A4 75.8%는 C0(76.2%), A2(75.0%)와 같다. 프롬프트 v2만으로 얻은 개선(E3-b 72.1 → 76.2%)에 Agent를 더 얹어도 더 오르지 않았다.
- **같은 규칙이 두 번 들어간 중복은 해도 득도 없었다.**
- **A4는 가장 비싸다.** 입력 토큰이 E3-b의 +22%(기본)·+10%(확장), LLM 호출 2배, 응답 8.1~9.2초(E3-b의 1.8~2.0배)다. 출력이 길어진 것(기본 177 → 259 토큰)도 한 원인이다.

## 5. 최종 설정에 대한 판단

Agent를 붙이는 것이 요구사항이므로 **E3-b + Agent v2 + 프롬프트 v2(`retry=0,v2=1,sys2=1`, A4)**를 Agent 구성으로 택한다. 기본 세트에서 가장 높고(83.0%) 행동 문항이 가장 균형 있으며, 확장 세트에서는 가장 좋은 설정(C0)과 같다. 숨기지 않고 적는다:

- **Agent의 품질 이득은 오차 범위다.** A4는 E3-b보다 두 세트에서 pass +3.3, +3.7%p지만 5%p 기준 안쪽이다. 이득을 말할 수 있는 근거는 행동 문항(되묻기·보류·거절)의 방향성뿐이고 문항 수가 적다.
- **품질 대비 비용으로는 C0(E3-b + 프롬프트 v2)이 낫다.** 확장 세트에서 가장 좋고(76.2%), 기본 세트에서 E3-b와 같으며(80.3%), 호출 1번·응답 4.4~4.7초다. Agent 요구사항이 없다면 C0이 최종 후보다.
- **프롬프트 v2는 Agent와 별개로 채택할 가치가 있다.** 확장 세트의 개선(+4.1%p)은 Agent가 아니라 프롬프트에서 나왔다.
- 원본 Agent(E7: 토큰 1.9배, 호출 3회, 응답 2.3배)에 비하면 A4는 비용이 훨씬 줄었다(토큰 +22%, 호출 2회).

## 6. 한계와 남은 것

- 기본 세트는 되묻기 8문항, 정정 7문항, 보류 12문항이라 행동별 수치는 방향만 본다.
- 확장 세트는 기대 행동이 거의 모두 '답변'이라 분기의 효과가 작다.
- 실행 32개는 코드를 커밋하기 전에 돌려 코드 버전이 `-dirty`로 기록돼 있다.
- 미검증: 확장 세트에서 Agent의 근거 준수·답변·보류 일치가 약간 낮은 원인(질문 분석의 잘못된 분기 추정, 지침 위치), `needs_caveat` 과다 판단의 원인, 정정 문항이 나빠지는 원인.
