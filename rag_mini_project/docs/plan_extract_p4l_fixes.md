## 1. 2단 문서 읽기 순서 (housing_policy_finance, insurance_terms_example, self_employed_debt)

### 원인 (확인함)
- pymupdf4llm 레이아웃 상자 자체는 **단별로 잘 나뉘어 있다**(상자 하나가 두 단에 걸치지 않음).
- 문제는 **상자 순서**: 위에서 아래로(y 순서) 정렬돼 왼쪽 단 상자와 오른쪽 단 상자가 번갈아 나온다.
  - 예: self_employed 1쪽 → 왼쪽 '자영업자 대출 동향' 제목 다음에 오른쪽 단 '각 641.9조원…'이 끼어듦
  - insurance는 가로 쪽에 A4 2쪽을 나란히 붙인 문서(1191×842). 왼쪽 반 = 인쇄 6쪽, 오른쪽 반 = 7쪽.
- 각주(`footnote`)·쪽 아래 넓은 상자는 두 단에 걸쳐 있다(한국은행 양식).

### 고칠 방법
`build_page()`에서 `chunk["page_boxes"]`를 쓰기 전에 **상자 순서만 다시 정렬**한다(본문 재추출 없음, `pos`로 글자 잘라 붙이기).
1. 단 경계 찾기: 상자들의 x 범위로 **어떤 상자도 걸치지 않는 세로 빈 띠**를 찾는다(쪽 가운데 30~70% 구간).
   - 걸치는 상자가 없고 양쪽에 상자가 충분하면 2단 쪽으로 본다(전 문서 공통 규칙, 파일 이름으로 정하지 않음).
2. 넓은 상자(경계를 걸치는 상자: 각주, 쪽 전체 제목, 넓은 표)를 **구분선**으로 삼아 쪽을 위→아래 구간으로 나눈다.
3. 구간마다 **왼쪽 단 상자 전부(위→아래) → 오른쪽 단 상자 전부(위→아래)** 순서로 놓는다.
4. `page-header`·`page-footer`는 기존처럼 둔다.
5. 그림 상자도 같은 규칙으로 정렬(그림 위치가 문단 사이에 맞게 들어가도록).

### 검증
- 위 3개 문서의 2단 쪽 전부: md 안 문단 순서가 '왼쪽 단 → 오른쪽 단'인지 확인
  - 자동: PDF 글자층을 단별(왼쪽 반/오른쪽 반 clip)로 읽은 순서와 md 문장 순서를 비교(순서 일치율)
  - 수동: self_employed 1쪽, housing_policy_finance 6쪽, insurance 4쪽을 직접 대조
- 1단 문서(housing_pension, policy_finance, retirement)는 결과가 **바뀌지 않아야** 한다(md diff로 확인).

## 2. 쪽 전체가 그림으로 잡힌 쪽의 제목 누락 (retirement 2쪽 '한 눈에 살펴보는 2025년 퇴직연금')

### 원인 (확인함)
- 레이아웃 모델이 2쪽 전체를 `picture` 상자 하나(같은 상자 3번 중복)로 잡았다.
- `force_text=False`라 그림 안 글자는 본문에서 빠지고, 한글 비율이 낮아 '설명 박스' 규칙에도 걸리지 않는다.
- 비전 지시문은 "본문은 무시"라서 쪽 제목을 옮기지 않았다.

### 고칠 방법
1. **그림 상자 안 큰 글씨 줄 살리기**: 글 상자로 살리지 않은 그림 상자에서, 글자 크기가 문서 본문 크기의 1.2배 이상인 줄을 제목으로 꺼낸다.
   예: `## 한 눈에 살펴보는 2025년 퇴직연금`. 숫자만 있는 줄(차트 값)은 빼고, 같은 상자 중복은 한 번만 쓴다.
2. **비전 항목 제목**: 지시문에 "그림 위나 옆에 적힌 소제목(예: '1 퇴직연금 운용현황')을 `[graph] 제목`의 제목으로 쓴다"를 추가한다.
   → 이 지시문 변경은 4번(box_2d)과 **한 번에** 반영해 비전 재호출을 한 번으로 줄인다.

### 검증
- retirement 2쪽 md에 쪽 제목과 7개 소제목이 들어가는지
- 6개 문서 '단어 회수율 낮은 쪽' 목록이 줄어드는지(현재 retirement 2쪽 0.85)
- 큰 글씨 규칙 때문에 차트 숫자가 본문에 새로 섞이지 않는지

## 4. 그림마다 잘라서 저장 (개선 방법 1: Gemini box_2d)

### 바꿀 내용
- `vision.py`의 `page_visual` 지시문: 항목 첫 줄을
  `[graph] 제목 | box=[ymin, xmin, ymax, xmax]` 로 쓰게 한다(쪽 이미지 기준 0~1000 정규화 좌표, Gemini box_2d 관례).
- `extract_p4l.py`의 `parse_visuals()`: 종류·제목·box를 함께 읽는다.
- 잘라내기: 쪽 PNG(200dpi)에서 box에 여백 3%를 더해 자르고 `images/<문서>/p{쪽}-g{n}.png`, `p{쪽}-i{n}.png`로 저장.
- 블록 표시: `image="…/p2-g1.png" page_image="…/p2.png"` (쪽 전체 이미지는 원본 확인용으로 남김)
- box가 없거나 이상하면(범위 밖, 면적 < 1%) 쪽 전체 이미지를 쓰고 블록에 `crop=page`를 남긴다.

### 비용·주의
- 지시문이 바뀌어 캐시 키가 달라지므로 **305쪽 전부 다시 호출**(약 15분, 5개 동시). 2번 지시문 변경과 함께 한 번에 한다.
- 다시 호출하면 비전 결과 글이 조금 달라질 수 있으니 검증을 다시 돌린다.

### 검증
- retirement 2쪽: 7개 그림이 각각 잘려 저장되는지(사용자가 보여 준 오른쪽 그림처럼)
- 잘린 이미지 표본 10장 눈으로 확인(제목·라벨이 잘리지 않았는지)
- `crop=page`로 빠진 비율 집계

## 6. 색칠한 칸으로 값을 나타내는 표/그래프 (housing_pension 85쪽 '가입연령별 선택 가능한 확정기간')

### 원인 (확인함)
- 칸에 글자가 없고 **칸 색칠(벡터 사각형)**로 범위를 나타내는 표(간트형). 나이 라벨 55~74와 행 라벨(30년형…)만 글자다.
- 규칙 표 로더는 빈 칸만 보고 표로 내지 않았고, 비전이 [graph]로 읽었는데 **두 값이 한 칸씩 틀렸다**.

| 행 | 비전(현재 md) | 벡터 좌표로 계산(정답) |
|---|---|---|
| 30년형 | 55~58 | **55~57** |
| 25년형 | 55~63 | 55~63 |
| 20년형 | 55~67 | **55~68** |
| 15년형 | 60~74 | 60~74 |
| 10년형 | 65~74 | 65~74 |

- 막대가 칸마다 색칠된 사각형이라 **좌표로 정확히 읽을 수 있다**(이전 파이프라인의 '벡터 수치화'와 같은 방식).

### 고칠 방법
1. 표 로더(`tables.py`)가 칸 글자와 함께 **칸 채움 색**을 본다: 회색·흰색이 아닌 색 사각형이 칸 면적의 절반 이상을 덮으면 색칠 칸으로 표시.
2. 본문 칸이 대부분 비어 있고 색칠 칸이 있는 표는 '색칠 범위 표'로 보고, 행마다 이어진 색칠 칸의 머리글 범위를 값으로 쓴다
   → `| 기간 | 가입연령(세) |` / `| 30년형 | 55~57 |` …, 블록에 `source=vector`.
3. 레이아웃이 이 영역을 표가 아니라 그림으로 잡아도 같은 검사를 그림 상자 안에서 한다(머리글 숫자 라벨 + 행 라벨 + 색 사각형이 있으면).
4. 같은 영역을 비전도 읽었으면 **벡터 결과를 우선**하고, 비전 블록은 빼거나 `checked_by=vector`로 남긴다. 둘이 다르면 로그로 남겨 검토.

### 구현 상세 (확정: 이 방식으로 간다)

**입력**: PyMuPDF `page.get_drawings()`의 채움 사각형(`fill` 색), `find_tables`의 칸 좌표, 칸 글자(기존 `_PageShim`).

**단계**
1. **색칠 사각형 모으기** (`extract_p4l.py`)
   - `fill`이 있는 사각형 중 '색' 있는 것만: RGB의 최대−최소 ≥ 0.15 (흰색·회색 배경 제외).
   - 쪽마다 한 번 모아 표 로더에 넘긴다.
2. **칸 색칠 판정** (`tables.py`, `extract_table(..., fills=None)` 인자 추가)
   - 격자 칸마다 색 사각형이 칸 면적의 50% 이상을 덮고 칸 글자가 없으면 색칠 칸(■).
   - 머리글 행(이미 구한 `n_header_rows`)의 색 배경은 판정하지 않는다(머리글 배경색 오탐 방지).
3. **색칠 범위 표로 바꾸기**
   - 조건: 본문 칸 중 색칠 칸이 30% 이상이고, 본문에 숫자 값이 없는 표.
   - 행마다 이어진 색칠 칸 묶음을 찾아 머리글 값으로 범위를 만든다: 55·56·57 칸 → `55~57`.
     묶음이 여러 개면 `55~57, 60~62`. 한 칸이면 `55`.
   - 출력: `| 기간 | 해당 범위 |` + 행마다 `| 30년형 | 55~57 |`. 왼쪽 위 머리글('기간')을 첫 열 이름으로, 표 위 단위 줄 '(단위: 세)'는 표 블록에 함께 둔다.
   - 블록 표시: `<!-- block: table … source=vector -->`
4. **그림으로 잡힌 영역도 확인**
   - 지금은 레이아웃 `table` 상자에서만 표 로더를 부른다. `picture` 상자 안에도 `find_tables` 표가 있으면 같은 판정을 하고,
     색칠 범위 표로 바뀌면 표 블록으로 넣는다(85쪽이 이 경우일 가능성이 큼 → 구현 첫 단계에서 확인).
5. **비전 결과와 겹침 처리**
   - 4번(box_2d) 적용 후: 비전 블록의 box가 벡터 표 영역과 50% 이상 겹치면 비전 블록을 뺀다.
   - 4번 전에는 제목으로 짝을 맞춘다(비전 제목 '가입연령별 선택 가능한 확정기간' ↔ 표 위 제목 줄).
   - 값이 서로 다르면 `logs/vector_vs_vision.jsonl`에 남겨 비전 오류율 집계(7번)에 쓴다.

**인터넷**: 필요 없음(좌표 계산뿐, 비전은 캐시).

### 검증
- 85쪽 5개 행이 위 정답과 같은지(30년형 55~57, 25년형 55~63, 20년형 55~68, 15년형 60~74, 10년형 65~74)
- 6개 문서에서 '색칠 범위 표'로 바뀐 표 목록을 뽑아 원본과 대조
  - 오탐 확인: 색 배경 머리글·강조 행만 있는 일반 표가 바뀌지 않았는지(숫자 값이 있는 표는 조건에서 빠짐)
- 기존 규칙 표 결과는 그대로인지(색칠 범위 표로 바뀐 표 외에는 md diff 없음)
- 골든셋 주택연금 문항 중 확정기간 관련 근거 확인

## 7. 비전 그래프 값 점검 (6번에서 드러난 일반 문제)
- 비전은 막대 끝 위치를 한 칸씩 틀리게 읽을 수 있다. 지시문은 '숫자 라벨로 적힌 값만'이지만 위치로 읽는 그래프에서는 지켜지지 않았다.
- 벡터 좌표가 있는 그래프는 6번처럼 좌표로 확인하는 것을 우선하고, 래스터 그래프는 표본을 골라 원본 이미지와 대조해 오류율을 기록한다(이번 퇴직연금 분포 그래프 대조는 모두 맞았음).

### 진행 중 발견해 함께 고친 것
- 2단 경계 검출이 짧은 각주 한 줄 때문에 실패하던 문제 → '걸치는 상자가 가장 적은 곳'을 경계로, 각주는 세지 않음
- 색칠 표시(■)가 머리글 빈칸에 새어 나와 표 검사를 통과해 버리던 문제 → 색칠 표가 아니면 머리글에서도 지움
- 두 열에 걸친 칸의 숫자가 두 열에 복사되던 문제 → 숫자는 놓인 열에만
- 위 첨자 주석 번호가 값에 붙어 틀린 숫자가 되던 문제(`(16.5`+`2)`→`(16.52)`) → `^` 표시(`(16.5^2))`, 본문 `1.88%^33)`)

### 남은 문제
- 그림 상자 안 글자 살리기 규칙이 일부 차트(라벨에 한글이 많은 차트)의 숫자 라벨까지 본문에 넣음(예: 주택정책금융 6쪽 '52.2 21.5 20 20 …'). 비전 graph 블록과 중복되는 잡음
- 세로쓰기 행 머리(‘저량/유량’)가 행마다 한 글자씩 붙음

### 계획과 다르게 한 것
- '줄 시작 위치가 한 줄기'가 아니라 '같은 높이에 나란히 놓인 줄의 비율'(20% 이상이면 칸 구조)로 판정했다. 문장 단은 들여쓰기·글머리표로 시작 위치가 여러 개라 줄기 수로는 가르기 어려웠다.
- 줄바꿈 자리 띄어쓰기는 `Joiner`를 pymupdf4llm 본문에 그대로 쓸 수 없어(줄 경계 위치를 모름) Kiwi 분석 + 같은 문서 증거 방식으로 바꿨다.

### 남은 문제

## 3차 수정: 읽는 순서와 제목 단계 (2026-10-21)

문제: 비전·다시 읽기 블록을 쪽 맨 끝에 붙여서, 그림 내용이 자기 제목이 아니라 그 쪽 마지막 제목 아래로 들어갔다(예: 보험약관 2쪽 도식이 `4 약관의 핵심 체크항목` 아래). 제목 단위로 parent를 나누면 그림이 엉뚱한 절에 붙는다.

| 고친 것 | 방법 |
|---|---|
| 읽는 순서 | 레이아웃 상자마다 읽는 순서 번호(order)를 갖게 하고, 그림 상자 앞뒤에서 본문 블록을 끊음. 비전 블록은 위치(box_2d)가 겹치는 그림 상자 바로 뒤에, 겹치는 그림 상자가 없으면 같은 단에서 바로 위 상자 뒤에, 위치를 모르면 쪽 끝에 둠. 영역 다시 읽기 블록은 자기 그림 상자 뒤 |
| 제목 단계 | 번호 배지가 붙은 영역 제목과 `**3** QR코드…` 같은 번호 배너 한 줄(굵은 번호 + 큰 글씨 한 줄)은 같은 쪽 번호 제목(`# **1**`)과 같은 단계로, 번호 없는 영역 소제목은 바로 앞 제목보다 한 단계 아래로 |
| 제목 속성 | graph·image 블록 표시에 `title="…"`을 남김(청킹 때 그림 제목 메타데이터로 사용) |
| 띄어쓰기 | 굵은 글씨 뒤 조사(`**보험약관** 은` → `**보험약관**은`) |
| 점검 | `logs/outline_<문서>.txt`: 그림이 있는 쪽의 블록 순서(제목 → 본문 → 그림)를 한 줄로. 점검에 '번호 제목 단계가 서로 다름' 추가 |
