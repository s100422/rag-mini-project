# RAG 실험 계획

기록 형식은 `docs/experiment_records.md`를 따른다. 모든 비교 실험은 `--baseline <기준 실험 ID>`로 돌려
`config.json`의 `changes`에 **바꾼 요소 하나만** 잡히는지 확인한다.

## 1. 질문 세트와 검색 대상

검색 범위가 다른 두 세트를 따로 평가한다. 세트끼리는 지표를 비교하지 않는다.

| 세트 | 검색 대상 PDF | 평가 문항 | 비고 |
|---|---|---|---|
| 기본 세트 | 용어집 1개 + 표준약관 15개 | 68개: positive 60 + 근거가 있는 negative 8 | negative의 '자료에 없음' 판단은 이 범위 기준(README) |
| 확장 세트 | 금융생활 가이드북 1개 + 추가 문서 6개 | 80개: 가이드북 20 + 추가 문서 60 | |

- 근거가 없는 negative 32개는 검색 지표가 없다. 답변 단계(확인·보류·거절)에서만 평가한다.
- 질문 유형 라벨은 `eval_labels/question_types.csv`에 있다(직접 붙이고 검수).
  - `question_type`: term(용어·제도·조항·표 이름을 직접 묻는 질문) / situation(상황을 풀어 설명한 질문)
  - `needs_table`: 표·그래프 수치를 읽어야 답할 수 있는 질문
  - 분포: 기본 세트 term 29 / situation 39, 확장 세트 term 10 / situation 70, 표 질문 30(확장 세트)

## 2. 기준 설정 (B0)

| 항목 | 값 |
|---|---|
| 청킹 | **일반 Recursive 500/50**. 문서 구조(조항·용어·제목)를 쓰지 않고 문서 본문 전체를 자른다. parent 없음. 제목·문맥 접두어 없음 |
| 분할 기준 | `["\n\n", "\n", ". ", " ", ""]`, 쪽 표시는 본문에서 빼고 쪽 위치만 기록 |
| 임베딩 | `models/gemini-embedding-001` |
| 검색 | similarity(코사인), **k = 5**(컨텍스트에 넣는 개수), HNSW ef_search 1000(전수 검색과 같음) |
| 결과 단위 | 청크 1개 = 컨텍스트 1자리 |
| 답변 생성 | Gemini Flash 계열, temperature 0, 프롬프트 v1 (RAG 단계에서 고정) |
| 평가 | 같은 질문 세트, k ∈ {1, 3, 5, 10}에서 지표 계산, 대표 지표는 k=5 |

B0은 세트마다 하나씩 만든다: `base_rec_c500_o50`(용어집+약관), `extended_rec_c500_o50`(가이드북+추가 문서).
지금 있는 `base_c350_o50`(조항·용어 parent-child 350/50)과 `extended_c500_o50`(쪽 단위 500/50)은 예비 실행이고,
아래 E3의 비교 대상으로 다시 쓴다.

## 3. 지표

| 지표 | 무엇을 보나 | 관련 실험 |
|---|---|---|
| hit@k, recall@k, all_hit@k, mrr | 필요한 근거가 컨텍스트에 들어왔는가 | 전부 |
| precision@k, dup_rate@k | 불필요하거나 중복된 결과가 얼마나 섞였나 | E1, E2, E6 |
| context_chars@k | 컨텍스트 양(답변 비용·잡음) | E1, E4, E6 |
| source_coverage@k | 정답 근거 원문 중 컨텍스트에 실제로 들어간 비율(근거가 잘렸는가) | E1, E2, E3, E4 |
| key_phrase_recall@k | 기준 답안 핵심 구절 중 원문에 그대로 있는 것의 포함률(기본 세트만) | E1, E2, E3 |
| latency_ms | 검색 시간 | E5, E6 |
| 답변 지표(RAG 단계) | must_include 포함, must_not_include 미포함, 인용(파일·쪽) 정확도, 근거 준수, 기대 행동(답변·확인·보류·거절) 일치 | E4, E7 |
| 비용(RAG 단계) | 모델 호출 수, 검색 횟수, 입력·출력 토큰 | E7 |

분석은 전체와 함께 `question_type`, `needs_table`, `source_doc`, `difficulty` 그룹별로 본다.

## 4. 비교 실험

각 실험은 B0에서 **한 요소만** 바꾼다. 나머지(질문 세트, 검색 대상, 임베딩, 검색 방식, k, 평가)는 고정한다.

| ID | 아이디어 | 바꾸는 요소 = 값 | 고정 | 주로 볼 지표 | 가설 |
|---|---|---|---|---|---|
| E1-a, E1-b | 청크 크기 | chunk_size = 300, 800 | 겹침 50, k 5 | source_coverage, hit, precision, context_chars | 작으면 근거가 잘리고, 크면 불필요한 내용이 섞인다 |
| E2-a, E2-b | 겹침 | chunk_overlap = 0, 100 | 크기 500, k 5 | source_coverage, hit, dup_rate | 겹침이 없으면 경계에 걸친 근거가 잘린다 |
| E3-a | 문서 구조 청킹 | 분할 단위 = 구조 단위: 용어집은 용어·정의, 약관은 조항, 가이드북은 제목·문단, 추가 문서는 쪽. 단위가 500자를 넘으면 그 안에서 Recursive 500/50 | parent 없음, 검색·k | hit, source_coverage, key_phrase_recall | 근거 단위와 청크 단위가 맞으면 정답이 한 청크에 온전히 담긴다 |
| E3-b | 구조 + parent-child | E3-a 단위를 parent로 두고 child 500/50을 검색, 결과는 parent | 그 밖은 E3-a와 같음 | hit, source_coverage, context_chars | **E3-a 대비** 한 요소(결과 단위) 변경. 컨텍스트가 길어지는 대신 근거가 온전해진다 |
| E4-a | 문맥 보존: 제목 | 청크 앞에 `[문서 제목 > 상위 제목]` 접두어(임베딩·컨텍스트 모두) | 청킹 B0 | hit(상황형), 답변 지표 | 짧은 청크가 어느 문서·조항인지 알 수 있어 검색·답변이 나아진다 |
| E4-b | 문맥 보존: 표 | 표는 행 경계에서만 자르고 조각마다 표 제목·머리행·단위·각주를 붙임(확장 세트) | 청킹 B0 | needs_table 그룹의 hit·source_coverage, 답변 수치 정확도 | 표 조각에 단위·머리행이 붙으면 수치 질문 답이 맞아진다 |
| E5-a, E5-b | 질문 유형별 검색 | method = bm25, hybrid(가중치 0.5) | 청킹 B0, k 5 | question_type별 hit·mrr | 용어형은 BM25, 상황형은 벡터가 낫고 hybrid가 둘을 절충한다 |
| E6-a, E6-b | 결과 양 | k = 3, 10 | 청킹·검색 B0 | hit, precision, dup_rate, context_chars | k가 크면 근거는 더 들어오지만 중복·잡음도 는다 |
| E6-c | 결과 구성 | method = mmr(λ 0.5) | k 5 | dup_rate, hit, all_hit(근거 2개 이상 문항) | 같은 쪽 청크 중복이 줄고 여러 근거가 필요한 문항이 나아진다 |
| E7 | Agent 구조 | 기본 RAG → 직접 설계한 Agent | 검색 설정·생성 모델·질문 세트 | 답변 지표, 비용, 시간 / question_type·expected_behavior별 | 여러 요소가 함께 바뀐다(아래) |

### E7 해석 규칙

기본 RAG와 Agent는 여러 요소가 함께 달라진다(질문 분석, 재검색, 근거 판단, 거절·확인 분기, 프롬프트 등).
- `changes`에 달라진 요소를 모두 남기고, 결과는 **전체 구성의 효과**로 해석한다.
- 특정 요소(예: 재검색)가 개선의 원인이라고 보려면 그 요소만 끄거나 켠 Agent 변형을 따로 돌려 확인한다(ablation).
- 검색 설정은 B0으로 고정한다. E1~E6에서 더 나은 설정을 찾았으면 '기본 RAG + 그 설정'과 'Agent + 그 설정'을 한 쌍으로 다시 비교한다.

## 5. 진행 순서

1. B0 컬렉션 2개를 만들고 B0 검색 평가(similarity, k=5) → 기준 실험 ID 확정
2. 설정만 바꾸면 되는 실험: E5(bm25·hybrid), E6(k 3·10, mmr)
3. 컬렉션을 새로 만드는 실험: E1, E2, E3-a, E3-b, E4-a, E4-b
   - 구현 필요: 문서 전체 Recursive 분할(근거 경계를 넘는 청크는 근거 ID 여러 개), 가이드북 제목·문단 파서,
     제목 접두어 옵션, 표 인식 분할
4. 기본 RAG 구현 → B0 위 답변 평가(답변 지표·비용 기록) → E4 답변 비교
5. Agent 구현 → E7, 필요한 ablation
6. 실패 사례 분석: `hit@5 = 0`(검색에서 놓침)과 `hit@5 = 1`인데 답변 오류(답변 단계에서 틀림)를 나눠 원인을 정리
